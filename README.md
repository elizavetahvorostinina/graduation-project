# Дипломный проект — веб-приложение химчистки

В репозитории представлены материалы анализа и проектирования веб-приложения химчистки: техническое задание, BPMN-модели бизнес-процессов, UML-диаграммы и ER-модель данных в приложении к ТЗ.

Опубликованный комплект содержит проектную документацию и модели. Исходный код приложения в репозиторий не включён; описанные ниже функции и технологии относятся к проектируемой системе.

## О проекте

Веб-приложение предназначено для самостоятельного оформления клиентом заказа на услуги химчистки и сопровождения заказа сотрудником: от приёма изделия до выдачи готовой вещи.

Клиент выбирает основные и дополнительные услуги, формирует корзину и после авторизации подтверждает заказ. Сотрудник уточняет сведения об изделии при его фактическом приёме, оформляет бумажную квитанцию, вносит скидку при необходимости и изменяет статус заказа.

## Пользователи и возможности

| Роль | Возможности по ТЗ |
|---|---|
| Неавторизованный пользователь | Просмотр и фильтрация каталога, работа с корзиной, просмотр пунктов приёма/выдачи на карте. Для подтверждения заказа требуется вход или регистрация. |
| Авторизованный клиент | Оформление заказа, выбор доставки и способа оплаты, добавление комментария, просмотр собственной квитанции и статуса, сохранение страницы заказа в PDF. |
| Сотрудник (администратор) | Вход через отдельную страницу, просмотр списка заказов, редактирование сведений об изделии, скидки и статуса, оформление бумажной квитанции при приёме вещи. |

Клиенту доступны только его собственные заказы. Служебные поля предназначены для сотрудника: тип загрязнения, описание изделия, дефекты изделия, иные дефекты изделия, скидка и статус.

## Основные бизнес-процессы

### Оформление заказа

1. Клиент открывает каталог и добавляет основные и дополнительные услуги в корзину.
2. При переходе к оформлению проверяется авторизация; при необходимости клиент входит или регистрируется.
3. Данные клиента подставляются из профиля. Клиент проверяет их, выбирает доставку и способ оплаты, при желании добавляет комментарий.
4. Приложение проверяет данные заказа. При ошибке отображается сообщение; при успешной проверке заказ и параметры оформления сохраняются.
5. Клиент получает доступ к странице заказа с текущим статусом и может сохранить электронную квитанцию в PDF.

### Приём и выдача изделия

1. Клиент передаёт изделие выбранным способом.
2. Сотрудник открывает заказ, осматривает вещь и заполняет служебные поля.
3. При приёме оформляется и подписывается бумажная квитанция; сотрудник устанавливает статус «Принято» и сохраняет изменения.
4. Заказ передаётся в чистку со статусом «В работе».
5. После завершения чистки устанавливается статус «Ожидает получения», затем заказ выдаётся клиенту.

В ТЗ согласованы статусы «Принято», «В работе» и «Ожидает получения». Статус сразу после онлайн-оформления, до фактического приёма вещи, требует уточнения. Отдельный статус после выдачи в опубликованных материалах не определён.

## Архитектура и данные

Предусмотрена клиент-серверная архитектура:

- **Клиентская часть:** отображение контента, оформление заказа и HTTP-клиент.
- **Серверная часть:** обработка запросов, авторизация, бизнес-логика и взаимодействие с БД.
- **PostgreSQL:** хранение клиентов, сотрудников, заказов, вещей, услуг и справочников.
- **Файловое хранилище:** изображения и документы.
- **JavaScript API Яндекс.Карт:** отображение пунктов приёма/выдачи и информации по геометкам.

ER-модель в ТЗ описывает заказы, вещи, клиентов, сотрудников, пункты приёма/выдачи, типы вещей, материалы, типы загрязнений, услуги и связующие сущности.

ТЗ предусматривает проверку прав доступа на сервере, валидацию входных данных, хранение паролей в виде защищённых хешей, защищённое соединение при обработке персональных данных и резервное копирование.

## Границы проекта

- Доставка выбирается между курьером и пунктом приёма/выдачи.
- Предусмотрен выбор оплаты картой онлайн или картой курьеру. Выбор способа оплаты не подтверждает проведение платежа внутри приложения; подключение платёжного эквайринга не входит в обязательный объём.
- Электронная квитанция — страница заказа, сохраняемая в PDF. Она не заменяет бумажную квитанцию, оформляемую и подписываемую при фактическом приёме вещи.
- Стоимость при оформлении заказа обозначена в ТЗ как ориентировочная.
- Автоматическая отправка уведомлений и отдельная аналитическая витрина не входят в обязательный объём.
- Численные показатели производительности и ресурсы эксплуатации в ТЗ не установлены и требуют отдельного согласования.

## Технологии и инструменты

Технологии, указанные в техническом задании:

- **Серверная часть:** Java 17.
- **Сборка:** Maven.
- **Клиентская часть:** HTML, CSS, JavaScript, UIkit CSS.
- **База данных:** PostgreSQL.
- **Инфраструктура:** Docker.
- **Внешняя интеграция:** JavaScript API Яндекс.Карт.

Нотации моделей: BPMN, UML и ER. Редактируемый исходник BPMN представлен в формате draw.io.

Начните с технического задания, затем изучите BPMN-процессы и UML-диаграммы. DOCX можно открыть в редакторе с поддержкой этого формата, SVG и PNG — в браузере или программе просмотра изображений, а `bpmn.drawio` — в draw.io / diagrams.net.

Команды сборки и запуска приложения не приводятся, поскольку репозиторий содержит документацию и модели без исходного кода.
